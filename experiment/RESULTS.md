# Experiment results (2026-10-15)

Question: can a model write correct programs in ail, a language created today that appears in
no training data, as reliably as in Rust and TypeScript?

## Setup

- 16 console tasks (stdin to stdout) with hidden tests generated by Python reference solutions.
  10 were seen by a pilot agent while the spec was being tuned; 6 are held out
  (`toposort lru intervals roman anagrams minesweeper`), written after the last spec change.
- Each (language, task) pair is one fresh agent. It reads the task and, for ail, the full
  `SPEC.md`, then writes the program once. No compiling, no testing, no second look.
- Graded by `grade.py`: compile, run every hidden test, compare stdout exactly.
- Repair round: failing pairs get the compiler output or the first failing test, once.
- Rust: `rustc -O`. TypeScript: `tsc --strict --lib es2022`, run on Node 25.

## Results: first attempt

| model | language | compiles | correct | tests passed | correct after 1 repair |
|---|---|---|---|---|---|
| Sonnet | ail | 16/16 | 15/16 | 95.8% | 16/16 |
| Sonnet | Rust | 16/16 | 16/16 | 100% | 16/16 |
| Sonnet | TypeScript | 16/16 | 16/16 | 100% | 16/16 |
| Haiku | ail v0.1.0 | 13/16 | 13/16 | 83.3% | 15/16 |
| Haiku | ail v0.1.1 | 15/16 | 15/16 | 95.8% | 16/16 |
| Haiku | Rust | 16/16 | 16/16 | 100% | 16/16 |
| Haiku | TypeScript | 16/16 | 16/16 | 100% | 16/16 |

"ail v0.1.1" is the same 16 Haiku programs, unchanged, graded by the compiler that infers
closing parentheses from indentation (see below). The only remaining failure called a helper
function the model never defined; one repair round fixed it.

Code size over the 16 Sonnet solutions: ail 24.9 KB, Rust 32.9 KB, TypeScript 21.9 KB.

## What we learned

1. **The cold-start risk did not materialize at this scale.** With nothing but a ~4,000-word
   spec in context, a model writes ail that compiles on the first attempt as often as Rust and
   TypeScript. Every Sonnet program compiled; the one wrong answer was a logic slip the agent
   itself pointed out (joining with `""` instead of `" "`).
2. **The s-expression weak spot is paren counting, not semantics.** 2 of Haiku's 3 failures
   were one missing or one extra `)`. Models indent correctly far more reliably than they count,
   so ail now treats indentation as a second witness: when the parens do not compile and the
   indentation-implied structure does, the compiler uses it (warning W0004) and `ail fix`
   writes it back. A program that compiles never changes meaning.
3. **These tasks are too easy to separate the languages.** All three are at or near 100% for
   both models. Measuring the advantages ail is designed for (no aliasing bugs, no silent
   overflow, no unhandled effects) needs harder tasks: mutation-heavy simulations where Rust's
   borrow checker bites, arithmetic above 2^53 where JavaScript numbers silently lose precision,
   and larger programs. That is run r3.
4. **Fairness bugs in the harness were found and fixed**: tsc included the DOM library, so a
   variable named `top` collided with `window.top`; with `--lib es2022` that program passes.

## Run r3: harder tasks (2026-10-16, ail 0.4 dev)

Eight new tasks (`tasks_r3/`, generated by `r3_tasks.py`) built to stress what r1/r2 did not: a limit
order book (mutation-heavy state), shortest paths with road lengths up to 10^15 (sums past 2^53, where
JavaScript numbers silently lose precision), an interpreter for a small language that must detect
64-bit overflow, an unbounded Game of Life, a preemptive CPU scheduler, JSON queries (Rust: no serde,
parser by hand), full text justification and 64-bit FNV-1a hashing. Same protocol: one fresh agent per
pair, the task and (for ail) `SPEC.md`, one write, no compiling or testing.

| model | language | compiles | correct on first attempt | same programs, fixed ail compiler |
|---|---|---|---|---|
| Sonnet | ail | 7/8 | 7/8 | 8/8 |
| Sonnet | Rust | 8/8 | 8/8 | 8/8 |
| Sonnet | TypeScript | 8/8 | 8/8 | 8/8 |
| Haiku | ail | 7/8 | 7/8 | 8/8 |
| Haiku | Rust | 8/8 | 8/8 | 8/8 |
| Haiku | TypeScript | 8/8 | 7/8 | 7/8 |

What happened:

1. **Both ail failures were compiler bugs, not model mistakes.** The SPEC says the branches of an `if`
   in statement position may have different types. The checker did not treat the last statement of a
   `while`/`for` body (Sonnet) or of a `match` arm in statement position (Haiku) as a statement, so
   `(if found (remove-at (mut book) i) (set ...))` was rejected. Fixed; the unchanged programs then pass
   every test. Writing the language with the agents keeps finding the spots where the compiler is
   stricter than the spec.
2. **TypeScript failed the interpreter task with Haiku** in a way the other two languages cannot:
   it rejected an out-of-range literal while parsing, before running the statements above it, so the
   program printed the error instead of the earlier output. (Its other "failures" in that task only
   exited with code 1 after printing the right error; the task did not specify an exit code, so those
   are counted as correct above.)
3. **The 64-bit traps did not catch the models this time.** Every TypeScript solution used `BigInt` for
   road lengths and hashes, and every Rust solution used `checked_*`/`wrapping_*` where needed. ail
   gained `checked-add/sub/mul` and `wrapping-add/sub/mul` for this run, and the models used them
   correctly from the spec alone.
4. **Models used the new features unprompted**: lambdas with `filter`/`find-index`/`sort-by`, `fold`,
   records with `with`, and string views are invisible but free.

Code size (Sonnet, all 8 tasks): see `runs/r3/`.
